# VAVA Automation Phase 2 — Google Meet Connect + Generate

## Goal
Add Google Meet generation directly from an existing VAVA session booking.

This phase must work independently from SMTP:
- Google connection/settings can be prepared now.
- The Generate button must be visible in the booking meeting card.
- If Google is not connected, generation must fail safely with a clear admin message.
- Once credentials/account are available, admin connects Google once and the same button generates the Meet link.
- Do NOT auto-generate after payment yet.
- Do NOT add reminders yet.
- Do NOT send booking emails automatically in this phase.

The existing manual meeting-link fallback MUST remain fully usable.

## 1. Google Meet settings page

Add submenu under VAVA Bookings:
Parent: `edit.php?post_type=vava_booking`
Menu title: `إعدادات Google Meet`
Page title: `Google Meet`

Capability:
Use `vava_booking_admin_capability()` if available, otherwise `manage_options`.

Store non-token configuration in:
`_vava_google_meet_settings`

Fields:
- enabled (0/1)
- client_id
- client_secret
- calendar_id (default `primary`)

Security:
- client_secret input renders BLANK.
- blank submitted client_secret preserves the saved secret.
- never print/log client_secret.
- show a read-only Redirect URI generated by WordPress:
  `admin_url('admin-post.php?action=vava_google_meet_oauth_callback')`
- concise connection status: Connected / Not connected.

Tokens:
Store separately in:
`_vava_google_meet_tokens`
Allowed stored values:
- refresh_token
- access_token
- expires_at

Never expose tokens in HTML, notices, logs, or URLs.

## 2. OAuth connection

Implement server-side OAuth 2.0 using WordPress HTTP APIs only; no external library.

Authorization endpoint:
`https://accounts.google.com/o/oauth2/v2/auth`

Token endpoint:
`https://oauth2.googleapis.com/token`

Scope:
`https://www.googleapis.com/auth/calendar.events`

Connect action:
`admin_post_vava_google_meet_connect`

OAuth callback:
`admin_post_vava_google_meet_oauth_callback`

Requirements:
- capability check
- nonce/state protection
- generate unpredictable state and store it in a short-lived transient tied to current admin
- `response_type=code`
- `access_type=offline`
- `prompt=consent`
- `include_granted_scopes=true`
- redirect_uri must exactly be the read-only URI shown on settings page
- exchange code server-side
- require a refresh token for successful persistent connection
- save tokens without exposing them
- redirect back with concise success/failure notice

Disconnect action:
`admin_post_vava_google_meet_disconnect`
- nonce + capability
- delete token option only
- preserve client ID/secret/calendar settings

## 3. Access-token helper

Create a helper that:
- returns current access token if not near expiry
- otherwise refreshes using refresh_token + client_id + client_secret
- uses `wp_remote_post()`
- updates access_token/expires_at
- returns WP_Error on failure
- never logs raw token responses/secrets

No Google API request should run when integration is disabled or disconnected.

## 4. Generate Google Meet handler

Add admin action:
`admin_post_vava_booking_generate_google_meet`

Triggered by a normal POST form/button from the existing booking meeting card.

Validation:
- nonce tied to booking ID
- booking admin capability
- booking exists and post type = `vava_booking`
- must be a SESSION booking, not digital/tangible/physical product order
- Google Meet integration enabled + connected
- booking date/time valid

Use current booking meta:
- service title
- booking date
- booking time
- booking duration
- booking/customer identifiers only as needed

Timezone:
Use existing VAVA booking shared timezone when available; otherwise WordPress timezone.
Construct timezone-aware start/end RFC3339 dateTimes.
Never assume UTC.

Create one Google Calendar event using REST:
POST
`https://www.googleapis.com/calendar/v3/calendars/{calendar_id}/events?conferenceDataVersion=1&sendUpdates=none`

Body:
- summary: `VAVA — {service title}`
- description: include only booking number and a short VAVA admin reference; do not include private questionnaire/health/customer notes
- start.dateTime + start.timeZone
- end.dateTime + end.timeZone
- conferenceData.createRequest.requestId = unique unpredictable id
- conferenceData.createRequest.conferenceSolutionKey.type = `hangoutsMeet`

Do NOT add the customer as a Google Calendar attendee in Phase 2.
VAVA's own email workflow will handle customer communication later and avoids duplicate Google invites.

### Idempotency / duplicate protection

Use booking meta:
- `_vava_booking_google_event_id`
- `_vava_booking_google_event_html_url`
- existing meeting meta from Step 1

Rules:
- if a valid existing meeting URL already exists, do NOT create another event.
- if Google event_id exists but meeting URL is still missing, GET that same event and try to resolve its Meet link instead of creating another event.
- never create duplicate Calendar events for repeated clicks.

Extract Meet URL from:
1. `hangoutLink`, else
2. `conferenceData.entryPoints[]` where `entryPointType=video`

Validate resulting URL with the existing meeting URL validator when available; otherwise require HTTPS + `meet.google.com`.

On success save into existing meeting meta:
- `_vava_booking_meeting_provider = google_meet`
- `_vava_booking_meeting_url`
- `_vava_booking_meeting_status = assigned`
- created/updated timestamps and user using current Step 1 conventions
- `_vava_booking_google_event_id`
- `_vava_booking_google_event_html_url`

If Google created the Calendar event but conference data is still pending:
- save event ID
- save meeting status `generating`
- show a clear notice that Google is still preparing the Meet link
- a repeated Generate click MUST refresh the same event, not create a duplicate

Do not use sleep loops longer than a trivial bounded check.
Do not use WP-Cron in Phase 2.
