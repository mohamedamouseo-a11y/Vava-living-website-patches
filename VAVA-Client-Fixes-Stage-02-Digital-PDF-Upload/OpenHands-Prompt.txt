Protected PDF Progress — RESET PERCENTAGE SPAN WIDTH
LIVE HOSTING / FTP DEPLOYMENT

CURRENT STATUS
The protected PDF upload itself works and the main progress panel is now visible.
A new, more accurate client screenshot shows that the TRACK inset is correct, but the percentage text (for example 11% / 88%) still sits on the extreme left edge.

CONFIRMED CSS CAUSE
The live admin-homepage.css contains a generic rule used by older/simple upload bars:

.vava-upload-progress span{
  display:block;
  width:0;
  height:100%;
  background:var(--vava-admin-accent);
  ...
}

The protected PDF percentage is ALSO a span:
[data-upload-progress-percent]

So even though the protected PDF HEAD ROW has the correct inner inset, the percentage span itself still inherits width:0 / height:100% / background behavior from the generic rule. Its text then visually overflows outside its intended grid cell, which is why the percentage appears against the far-left panel border while the progress track is correctly inset.

- modify percentages
- modify AJAX/PDF processing
- modify the outer progress panel geometry
- modify the already-correct track inset
- globally remove or rewrite .vava-upload-progress span because other homepage/media upload controls may depend on it
- modify unrelated CSS
