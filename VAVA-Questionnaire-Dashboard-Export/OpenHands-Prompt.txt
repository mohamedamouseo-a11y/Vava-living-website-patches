==================================================
GOAL
==================================================

Add a dedicated WordPress Dashboard interface for the EXISTING VAVA questionnaires.

Required admin experience:

Bookings / حجوزات VAVA
  -> Questionnaires / الاستبيانات

Inside the page provide two tabs:

1) Manage Questionnaires
2) Responses

This is an ADMIN-ONLY feature.
Do not change the customer-facing questionnaire workflow.

==================================================

==================================================

- beginning
- midpoint
- impact

Current canonical settings are stored on the Booking page under:
_vava_booking_questionnaires

Normal booking questionnaire submission:
_vava_booking_questionnaire

Impact questionnaire submission:
_vava_booking_impact_questionnaire

Current submission structure includes fields such as:
- type
- title
- language
- completed_at
- answers
- snapshot

The saved snapshot is important and MUST be used to label historical response data whenever available.

Do NOT create a second questionnaire storage system.
Do NOT migrate existing response data unless an actual compatibility issue is found and documented.

STEP 4 — RESPONSES TAB
==================================================

Build a response browser from EXISTING vava_booking records only.

A booking can contain:
- one Beginning or Midpoint response in _vava_booking_questionnaire
- an Impact response in _vava_booking_impact_questionnaire

If available, reuse:
vava_booking_questionnaire_all_booking_data( $booking_id )

Display one row PER QUESTIONNAIRE RESPONSE, not merely one row per booking.

Required columns:
- Booking ID
- Questionnaire type/title
- Completed/submitted date
- Customer name
- Customer email
- WhatsApp
- Service/session
- Appointment date
- Appointment time
- Booking status
- Questionnaire language
- View response

Use booking metadata already present in the current system, including where available:
_vava_booking_customer
_vava_booking_service_title
_vava_booking_date
_vava_booking_time
_vava_booking_status
_vava_booking_language

Response details:
- show section/group title
- question label
- human-readable answer
- use the SAVED questionnaire snapshot first
- fallback to current settings only if snapshot is missing
- for radio/checkbox values, translate stored internal option values using the snapshot option labels
- escape all output

Do not expose raw serialized meta.

==================================================
STEP 6 — EXCEL EXPORT
==================================================

Add a visible button:
Download Excel / تنزيل Excel

Use a secure admin-post action, for example:
vava_questionnaires_export

Requirements:
- capability check
- nonce check
- export current sanitized filters when practical
- no-cache/private headers
- Content-Disposition attachment

Primary format:
.xlsx

Do NOT add Composer or a third-party plugin.

Preferred implementation:
- use PHP ZipArchive when available
- generate a minimal valid XLSX package using inline strings
- keep all cell content as safe text
- preserve UTF-8 Arabic text
- prevent spreadsheet formula injection by never writing user values as formula cells

If ZipArchive is not available:
- fall back to UTF-8 BOM CSV
- use a .csv extension
- make it Excel-compatible
- report the fallback clearly in the final report

Export structure:
One response per row.

Metadata columns should include at minimum:
- Booking ID
- Questionnaire Type
- Questionnaire Title
- Completed At
- Customer Name
- Customer Email
- WhatsApp
- Service
- Appointment Date
- Appointment Time
- Booking Status
- Language

Then include questionnaire answer columns using human-readable question labels.

For mixed questionnaire types, either:
A) use a union of all question columns in one sheet, leaving irrelevant cells blank, OR
B) use separate sheets per questionnaire type if the implementation remains simple and robust.

Do not make the export depend on current question text only. Prefer saved snapshot labels for historical submissions.
