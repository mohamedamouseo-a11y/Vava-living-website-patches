==================================================
PHASE GOAL
==================================================

Fix ONLY this issue:

The WordPress login page does not reliably log in on the first attempt and the user has to refresh the page first.

The required final behavior is:
- Open wp-login.php in a brand-new private/incognito session.
- Enter valid username/password.
- Click the normal WordPress login button once.
- Dashboard opens immediately.
- NO refresh.
- NO press-and-hold verification.
- NO extra AJAX challenge before login.

Keep the VAVA visual login design.
Keep native WordPress username/password authentication.
Do not bypass authentication.

==================================================
ROOT CAUSE TO REMOVE
==================================================

The VAVA theme currently has a custom press-and-hold login guard in:

wp-content/themes/vava-living-theme-ar-v1/inc/admin-brand-vava.php
wp-content/themes/vava-living-theme-ar-v1/assets/js/login-vava.js

The old flow:
- renders a `data-vava-login-hold` control,
- creates a nonce,
- calls `vava_login_hold_start`,
- calls `vava_login_hold_verify`,
- hides/disables the normal submit button,
- requires `vava_login_hold_token`,
- rejects the login POST through an `authenticate` filter when the token is absent/invalid.

This custom gate is RETIRED in Phase 01.

Do NOT try to repair the press-and-hold flow.
Remove it from the active login path.
